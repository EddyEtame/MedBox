### Committing as Eddy, not as somebody else

The environment this was built in exported `GIT_AUTHOR_NAME` and friends, and
those **silently beat `git config`**. Several commits nearly went out under the
wrong name. On Eddy's own machine `git config user.name` is enough, but check
once:

```bash
git log -1 --format='%an <%ae>'
```

Check it **before** pushing, not after. Rewriting a pushed commit to fix an
author is a worse afternoon than reading one line.

## The one design decision, and the two ways to break it

**The AI never touches a measurement.** Sensors → NEWS2 → screen is the fast
track and has no model in it anywhere. Hypotheses, narration and the
microphone are the slow track, and the slow track is allowed to die.

That is the answer to almost every question a jury will ask, so it has to stay
true. It is enforced in two places, because it can be broken in two different
ways:

**In Python.** Nothing in `server/triage.py`, `server/sensors/` or
`server/db.py` may import from `server/ai/`. There is a test.

**In the browser, which is where it actually broke.** A missing file is not an
import error in a browser. It is `undefined`, and `undefined.setAvailable(...)`
throws inside the WebSocket `onmessage` handler. The socket keeps delivering,
so nothing looks disconnected — the handler just dies partway down, ten times a
second, and every line below the throw stops running. **The board freezes with
plausible numbers on it,** which is the worst failure this product has, and it
arrives through a `<script>` tag.

So every call into `MedBox.voice` or `MedBox.mic` is guarded
(`if (m.ears && MedBox.mic)`), including the load-time `wireVoice` block whose
early return otherwise strands everything wired after it.
`tests/test_the_slow_track_cannot_stall_the_board.py` fails on any bare call.
`MedBox.assessment` is deliberately **not** guarded: the assessment panel
cannot exist without it, so it is not optional and pretending otherwise would
be noise.

## What is built

- **NEWS2 triage** (`server/triage.py`) — Royal College of Physicians 2017,
  four of the seven parameters, single-parameter-3 escalation, every result
  carrying which parameters were actually measured. Deterministic, works with
  the AI off, and defensible in front of a jury because it is a real clinical
  standard rather than something invented for a school project.
- **The 3D ship console** (`web/ship.js`, raw WebGL, no libraries) and **the
  flat board** (`web/app.js`). Same feed, same data. `/` is the ship, `/board`
  is the flat one, and the flat one exists so a machine with no working WebGL
  still runs the entire demo.
- **Quarantine** (`server/quarantine.py`) — fever plus either desaturation or
  raised respiration. A zone is sealed from the first occupant; capacity only
  governs new arrivals; overflow is reported as *awaiting a bed* and is drawn
  in red on both views.
- **The AI layer** (`server/ai/`) — Ollama, schema-constrained. It cannot
  diagnose, prescribe, or restate urgency, because those fields do not exist
  in the schema it decodes under, and `validate.enforce()` rebuilds the answer
  from the schema's own keys so nothing it invented can travel through.
  Verified live against `tools/fake_ollama.py --rogue`.
- **Speech, both directions.** Out: pre-rendered Piper clips committed to the
  repo, so the demo laptop needs no speech engine. In: hold-to-speak,
  transcribed by faster-whisper from `models/faster-whisper-base` on the same
  machine. Deliberately **not** the browser's Web Speech API, which ships the
  audio to Google and would quietly undo the whole offline claim.
- **The self-explaining guide** (`server/ai/capabilities.py`) — the manifest is
  data the station owns. When the assistant is up it narrates it in its own
  words; when it is dead the station renders the same facts plainly. The model
  is the voice, never the source, because the explanation must not vanish at
  the moment the system is proving it does not need the model.
- **The printed guide** (`docs/USER_GUIDE.md`) — generated from that manifest,
  from `config.toml` and from `triage.py` itself. `tools/guide.py --check`
  fails the suite when it drifts.
- **Scenarios** (`scenarios/*.yaml`) — `contamination` is the one to demo.
  Demo from a scenario, never from live sensors: a rehearsed replay cannot
  embarrass you in front of a jury and live hardware can.

145 tests. `python -m pytest tests/ -q`.

## Traps already paid for

Do not re-learn these.

**Windows PowerShell 5.1**

- Anything a native program writes to stderr becomes an error *record*, and
  under `$ErrorActionPreference = "Stop"` that record is terminating. Python
  prints its banner to stderr. An early `setup.ps1` set `Stop` and probed
  python's version; the banner killed setup before `.venv` existed, and
  everything after failed for the obvious downstream reason — which looked
  like four problems instead of one. `setup.ps1` uses `Continue` and merges
  with `2>&1`, never `2>$null`.
- A relative path needs a leading `.\`. `.venv\Scripts\python` is not
  "command not found" — PowerShell tries to *load it as a module* and the
  error does not even mention paths. There is a test that scans every file for
  the unguarded form.
- `Get-Command` proves a file is on PATH and nothing more. `py.exe` lives in
  `C:\Windows` and survives Python uninstalls; the Store alias stubs in
  `%LOCALAPPDATA%\Microsoft\WindowsApps` are on the user PATH by default and
  often sit *ahead* of a python.org install. Probe every match, and probe the
  version, not just that it starts.
- `Set-Location -Path` treats `[` and `]` as wildcards. Use `-LiteralPath`.
- `$LASTEXITCODE` is session state, not per-statement state. Clear it before
  the call you are about to check.
- `$args` is an automatic variable. Assigning to it is not what you meant.
- A BOM-less `.ps1` is decoded with the system ANSI code page, so keep
  `setup.ps1` pure ASCII. There is a test.

**Python and the console**

- `cp1252` has no `✓` or `✗`. Printing them on a stock Windows console raises
  `UnicodeEncodeError` and exits 1. `tools/assets.py` reconfigures stdout to
  UTF-8 where it can and falls back to ASCII marks where it cannot.
- Detect a virtualenv with `sys.prefix`, never `Path(sys.executable).resolve()`
  — a venv's `python` is a symlink to the system interpreter, so resolving it
  walks straight out of the venv you are trying to detect.
- `input()` writes its prompt to the console only when stdin **and** stdout are
  a tty. Pipe the output to a file and the prompt goes into the file while the
  process blocks on a blank screen, with no timeout. Use `confirm()` in
  `setup.py`, and `-y` when nobody is there to answer.
- Python validates a `.pyc` on `(mtime, size)`. Two versions of a file with the
  same length, written in the same second, are indistinguishable, and pytest
  will run the stale bytecode. This wasted real time during verification. When
  a test result surprises you, `find . -name __pycache__ -exec rm -rf {} +`
  before believing it.

**Verification**

- A guard test is only worth having if you have watched it go red. Break the
  thing, run the test, confirm it fails, restore. An earlier browser check
  compared `document.body.innerText` and reported "not moving" in every case
  including the healthy one — it was measuring nothing and passing.
- Two defects lived on screen for days and were invisible in code review: the
  quarantine occupancy bar never filled (`.zfill` is a span inside a grid item,
  and width and height do not apply to a non-replaced inline element), and the
  microphone button was revealed by `attach()` on any browser that can record,
  regardless of whether a speech model existed. Both were found by opening the
  page. **Open the page.**
- Playwright: the board repaints ten times a second, so an `ElementHandle`
  detaches under you. Use `page.click('.row')`, which retries.
- Find a running station by PID — `pgrep -af python` — not by searching for
  "uvicorn". The launcher is `medbox.py`, and looking for the wrong string
  once cost an hour of debugging code that was never being served.
